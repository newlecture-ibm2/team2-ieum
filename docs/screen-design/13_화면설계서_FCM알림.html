(시스템) 브라우저 네이티브 다이얼로그
ieum.com
🔔 ieum.com에서 사용자에게 다음 권한을 요청합니다:
• 알림 표시
트리거 흐름 정책
① 사용자가 마이페이지 > 알림 설정 > "전체 푸시 알림" 토글 ON 수행
② Notification.permission 브라우저 상태를 우선 확인
③ 상태가 "default" 일 시 브라우저 권한 요청 다이얼로그 표시 (위 목업 화면)
④-A "허용(granted)" → Firebase Messaging 토큰 발급 후 서버 전달
④-B "차단(denied)" → 안내 메시지(Toast) 표시 및 토글 OFF 상태로 원복
⑤ 추후 권한 상태가 "denied"인 상태에서 사용자가 다시 토글을 켤 경우
    → 브라우저 설정에서 직접 변경하도록 유도 토스트 팝업 렌더링

Description

Summary.

  • FCM 푸시 알림 수신을 위한 브라우저 기본 권한 요청 다이얼로그
  • 개발자가 수동으로 렌더링 불가능하며, 환경에 따라 UI가 다름
  • 허용 여부에 따른 프론트엔드 상태 변경/토큰 관리에 대한 분기 규칙 포함
1 브라우저 주소 표시줄
HTTPS 적용 상태에서만 Service Worker 및 FCM 가능
자물쇠 아이콘으로 보안 연결 명시
2 권한 요청 메시지
"ieum.com에서 알림을 표시하려고 합니다."
3 차단 버튼
거부 시 Notification.permission = "denied"로 저장되며 영구적으로 토글 OFF 처리
4 허용 버튼
승인 시 firebase-messaging-sw.js가 활성화됨
서버 API에 디바이스 토큰 적재 후 알림 환경 구성 완료
5 정책 및 플로우 안내
다양한 예외 상황(이미 권한 거부 상태 등)에 맞는 UX 처리 플로우
