Summary.

  • 마이페이지 내 알림 수신 설정 섹션
  • 알림 유형별 ON/OFF 토글로 세부 제어

1설정 섹션 타이틀
"🔔 알림 설정" — 알림 관련 설정 영역
2전체 푸시 알림 토글
· ON → FCM 토큰 등록 (POST /api/users/me/fcm-token)
· OFF → 토큰 삭제, 모든 하위 알림도 비활성
· 첫 ON 시 브라우저 알림 권한 요청 (UI-FCM-003) 트리거
3토글 스위치
ON: 보라색 / OFF: 회색
토글 변경 즉시 서버에 설정 저장
4세부 알림 항목
· 축제 시작 알림: 즐겨찾기 축제 D-1 알림
· 축제 종료 알림: 후기 작성 유도
· 공지사항 알림: 새 공지 등록 시
· 댓글 알림: 내 글에 댓글 시
각 항목별 설명 텍스트 표시
5개별 알림 OFF 상태
회색 토글로 비활성 상태 표시
전체 알림 OFF 시 모든 항목 비활성+비활성화

Check Point

🔒 festa-connect.com
🔔 festa-connect.com에서 알림을 보내려고 합니다.
📋 트리거 흐름
① 사용자가 마이페이지 > 알림 설정 > "전체 푸시 알림" ON
② Notification.permission 상태 확인
③ "default" → 브라우저 권한 요청 다이얼로그 표시
④-A "허용" → FCM 토큰 발급 → 서버에 토큰 등록
④-B "차단" → 안내 메시지 표시, 토글 OFF로 복원
⑤ "granted" → 바로 FCM 토큰 발급 진행
⑥ "denied" → "브라우저 설정에서 알림을 허용해주세요" 안내

Description

Summary.

  • FCM 푸시 알림을 위한 브라우저 네이티브 권한 요청
  • 개발자가 직접 만드는 UI가 아닌 시스템 다이얼로그
  • 트리거 조건과 분기 흐름을 정의
1브라우저 주소 표시줄
HTTPS 필수 (FCM은 보안 컨텍스트 요구)
🔒 아이콘으로 SSL 인증 표시
2권한 요청 메시지
"festa-connect.com에서 알림을 보내려고 합니다"
브라우저별 UI 상이 (Chrome/Firefox/Safari)
3차단 버튼
클릭 시 Notification.permission = "denied"
알림 토글 OFF로 복원 + 안내 메시지 표시
"denied" 상태는 브라우저 설정에서만 해제 가능
4허용 버튼
클릭 시 permission = "granted"
→ Firebase SDK로 FCM 토큰 발급
→ POST /api/users/me/fcm-token으로 서버 등록
→ Service Worker 등록 완료
5트리거 흐름도
전체 분기 로직 정리:
· default → 권한 요청
· granted → 토큰 발급 진행
· denied → 안내 메시지 + 브라우저 설정 유도

Check Point

· Firebase SDK 초기화 필요 (firebase-messaging)
· Service Worker: firebase-messaging-sw.js 등록
· HTTPS 환경 필수 (localhost는 예외)
· FCM 토큰은 디바이스+브라우저별 고유
