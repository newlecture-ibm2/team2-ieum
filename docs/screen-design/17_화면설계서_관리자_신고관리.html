Description

Summary.

  • 사용자가 신고한 콘텐츠(게시글, 댓글, 리뷰)를 관리하는 화면
  • v2: 인라인 패널 → 모달 기반으로 변경
  • KPI 카드 (전체/대기중/처리완료/반려) + 상태 필터
  • 모달: 신고 정보 → 원문 → 답변(필수) → 처리
  • API_ADM_0050, 0053 연동
1 관리자 사이드바 네비게이션
· 현재 메뉴(신고 관리)는 보라색 활성 표시
2 페이지 타이틀 + 대기 건수 배지
· "🚨 사용자 신고 관리" 제목
· 우측에 대기중 건수 빨간 배지 표시
3 KPI 스탯 카드 (4종)
· 전체 / 대기중 / 처리완료 / 반려
· 클릭 시 해당 상태로 필터 (토글)
· 활성 카드는 보라 테두리 강조
4 신고 목록 테이블
API: GET /api/admin/reports (API_ADM_0050)
· 컬럼: 신고자, 유형, 사유, 상태, 관리
· 행 클릭 또는 [처리하기]/[이력 보기] 클릭 → 모달
5 관리 버튼 (상태별 변경)
· PENDING → [처리하기] (보라 버튼)
· RESOLVED/REJECTED → [이력 보기] (회색 버튼)
6 신고 상세 모달 (v2)
· 배경 오버레이 + 중앙 모달
· 섹션: ① 신고 정보(2열) ② 원문 ③ 답변 ④ 버튼
7 신고 대상 원문 영역
· 원문 API 연결 시: 작성자 / 작성일 / 내용(3줄) 표시
· 없거나 삭제된 경우: "이미 삭제된 콘텐츠입니다" 표시
8 처리 답변 영역 (PENDING만)
· 답변 템플릿 버튼 5종 (스팸/욕설/허위정보/정책위반없음/기타)
· textarea (필수, 최소 10자, 글자수 표시, auto-expand)
· RESOLVED/REJECTED → readonly 이력 카드로 대체
9 모달 하단 액션 버튼
· [닫기] — 모달 닫기
· [신고 반려] — DISMISS 처리 (파란 아웃라인)
· [신고 대상 {유형} 삭제] — DELETE 처리 (빨간 버튼)
· 삭제 버튼 문구는 target_type에 따라 동적 변경
· 답변 10자 미만이면 disabled
🎯 Event Description
E1 행 클릭 / [처리하기] 클릭
· 트리거: 테이블 행 또는 [처리하기] 버튼 클릭
· 동작: 신고 상세 모달 오픈 (PENDING → 답변 폼 표시)
E2 [이력 보기] 클릭
· 트리거: 처리완료/반려 건의 [이력 보기] 클릭
· 동작: 상세 모달 오픈 (readonly 이력 표시)
E3 답변 템플릿 선택
· 트리거: 템플릿 버튼 클릭
· 동작: textarea에 사전 정의된 답변 자동 입력
E4 신고 반려 (Dismiss)
· 트리거: [신고 반려] 클릭
· 동작: 답변 유효성 검사(10자↑) → API 호출 → 모달 닫기 → 목록 갱신
· API: PATCH /api/admin/reports/{id}/process (actionType: DISMISS)
E5 대상 콘텐츠 삭제 (Delete)
· 트리거: [신고 대상 {유형} 삭제] 클릭
· 동작: confirm 확인 → 답변 유효성 검사(10자↑) → API 호출 → 모달 닫기 → 목록 갱신
· API: PATCH /api/admin/reports/{id}/process (actionType: DELETE)
E6 KPI 카드 클릭 (필터)
· 트리거: 상단 KPI 카드 클릭
· 동작: 해당 상태로 목록 필터 (토글 방식 — 같은 카드 재클릭 시 전체로 복귀)

Check Point

· 관리자(ADMIN) 권한 검증 필수
· 반려/삭제 모두 답변(message) 필수 — 미입력 시 처리 불가
· 삭제 버튼 문구는 target_type별 동적 변경 (리뷰/게시글/댓글)
· 원문 조회 API 미구현 시 "삭제된 콘텐츠" 표시
· 처리 완료 후 목록 즉시 갱신 (API 재조회)
· 사용자 측 신고내역/답변 확인 기능은 후속 범위
· report_responses 테이블에 답변 저장 → 이력 조회 가능
